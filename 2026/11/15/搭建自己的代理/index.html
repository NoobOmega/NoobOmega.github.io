各协议含义

以前用一键脚本的时候，只知道一路回车，屏幕上弹出一堆 VLESS、REALITY、Vision、gRPC，根本不知道分别干嘛的。现在倒是学会了，整理一下。

VLESS

全称是 VMess Less，顾名思义精简版的VMess。以前的 VMess 协议本身会对传输的数据做一次对称加密，但现在互联网上几乎所有的流量本来就已经套了一层TLS了，代理层再加密一次纯属脱裤子放屁。
所以 VLESS 的设计思路非常简单：不做任何数据加密，只负责身份认证（ UUID 判断用户）和数据转发。至于传输安全性，全权交给外层的 TLS 或者 REALITY 去负责。

REALITY

GFW很阴，会主动探测你的服务器看是不是在进行科学上网(伪装成普通用户去连接你的服务器 IP，观察返回内容). 因此我们需要REALITY.他的主要功能有下面几点:

  1. 服务端保存一对密钥里的私钥，客户端配置文件里保存对应的公钥和 ShortId
  2. 客户端吧这俩个东西进行伪装后（用自己的临时私钥和服务端公钥算出共享密钥，把认证信息和 ShortId 加密），塞进 TLS 握手包的 Session ID 字段里（在 TLS 1.3 里这个字段本身就像一串随机数，用来藏东西刚好天衣无缝），
  3. 服务端拿着这个字段进行验证，如果验证失败，比如你是GFW。服务端会直接把整条 TCP 连接转发给目标伪装网站（比如加州理工官网），由这个服务器完成后续的 TLS 握手并返回原版网页和真证书。很牛逼。
  4. 如果验证成功，就进行正常的代理操作。

注：挑选伪装目标 dest 时，要求对方必须支持 TLS 1.3 和 HTTP/2，不能是国内或被墙域名，且尽量选与 VPS 网络延迟低的站点，这里我用的www.caltech.edu。

VISION

我们通过代理访问 HTTPS 网站时，外层是代理隧道的 TLS，内层是目标网站自己的 TLS
在握手阶段，这种流量很有规律，容易被 DPI 深度包检测模型识别出来。
Vision 主要是为了对抗DPI，主要做了两件事：

  1. 内层握手随机填充：在检测到内层 TLS 握手数据包时，自动往里填充随机长度的数据，打乱固定的包长特征，让检测模型抓瞎。
  2. 直通透传与内核：一旦内层握手结束进入本身就已经加密的 Application Data 阶段，Vision 就会停止外层的重复包裹。

注：Vision 只能运行在 RAW TCP + TLS/REALITY 上

GRPC

延迟很高，被逐渐废弃的一个协议，而且他的TLS流量特征不够隐蔽，这里我们不打算使用。

socks

一个应用层协议，和https在同一层，但SOCKS5 协议本身是不提供传输层加密的，所以它只能待在境外那半截链路里（Azure -> 住宅代理服务器），负责最后一跳的出口转发，不要直连，否则直接被墙。

XRAY

搞懂上面这些协议，就明白 vasma 和 Xray 的分工了：vasma 只是方便我们安装和修改配置的脚本工具，转发流量的是Xray-core。

Xray核心由三部分组成：

  1. Inbounds（入站）：负责在指定端口监听并接收客户端连接（比如用 VLESS + REALITY + Vision 接住国内发来的流量）。
  2. Routing（路由引擎）：流量进来后，根据协议、域名、目标 IP、端口以及来源入站标签，从上到下匹配规则，决定把流量交给哪个出站处理。
  3. Outbounds（出站）：负责把流量发出去，比如直接出网（freedom）、丢进黑洞屏蔽（blackhole），或者转发给下一跳代理（socks）。
